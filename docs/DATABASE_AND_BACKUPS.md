# پایگاه داده و پشتیبان‌گیری کی‌داره

## دیتابیس کجاست؟

بک‌اند پروژه Flask است و از SQLite استفاده می‌کند. مسیر پیش‌فرض فایل پایگاه داده:

`instance/kidareh.sqlite3`

فایل واقعی دیتابیس در زمان اجرا ساخته می‌شود و عمداً در Git قرار نمی‌گیرد. جداول کاربران، ویترین‌ها، کالاها، تگ‌های پولی و سفارش‌ها نیز توسط کد برنامه ایجاد یا تکمیل می‌شوند.

## نکته مهم در هاست

اگر فایل‌سیستم هاست موقت باشد، اطلاعات ممکن است بعد از deploy یا restart از بین بروند. در پنل هاست یک persistent disk/volume بساز و متغیر `DATABASE_PATH` را به مسیری داخل همان volume تنظیم کن. `UPLOAD_FOLDER` را نیز به مسیر پایداری روی همان volume یا فضای پایدار دیگری متصل کن تا عکس‌های کالاها باقی بمانند. تنظیم متغیر محیطی به‌تنهایی کافی نیست؛ مسیر باید واقعاً روی volume متصل‌شده باشد.

## ساخت نسخه پشتیبان

مسیر واقعی دیتابیس را با `DATABASE_PATH` تنظیم کن، سپس:

```bash
python scripts/backup_sqlite.py
```

برای ذخیره نسخه پشتیبان در محل دیگر:

```bash
python scripts/backup_sqlite.py --output-dir /مسیر/پشتیبان-امن
```

این ابزار از API پشتیبان‌گیری SQLite استفاده می‌کند و صحت فایل خروجی را با `PRAGMA integrity_check` بررسی می‌کند. نسخه‌های پشتیبان شامل اطلاعات خصوصی حساب‌ها و سفارش‌ها هستند؛ آن‌ها را خارج از پوشه عمومی سایت، با دسترسی محدود و ترجیحاً روی فضای جداگانه نگه دار.

قبل از بازیابی، سرویس را متوقف کن و ابتدا بازیابی را روی یک کپی آزمایش کن. بررسی `/api/health` فقط دسترسی به دیتابیس را می‌سنجد و تضمین نمی‌کند که volume میزبان پایدار است.


## بازیابی نسخه پشتیبان

ابتدا سرویس وب را متوقف کنید تا هنگام بازیابی هیچ نوشتنی انجام نشود. سپس نسخه پشتیبان را بررسی و بازیابی کنید:

```bash
python scripts/restore_sqlite.py --backup /مسیر/امن/kidareh-YYYYMMDD.sqlite3 --database "$DATABASE_PATH" --yes
```

اسکریپت پیش از جایگزینی، فایل پشتیبان را با `PRAGMA integrity_check` بررسی می‌کند و در صورت وجود دیتابیس فعلی، یک کپی از آن نگه می‌دارد. بازیابی را ابتدا روی نسخه آزمایشی انجام دهید. فایل پشتیبان حاوی داده‌های خصوصی است؛ آن را در مسیر عمومی سایت یا مخزن Git قرار ندهید.
