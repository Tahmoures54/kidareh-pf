# برنامه تست واقعی کاربری — کی‌داره

هدف: اعتبارسنجی اولویت‌های UX با **فروشندگان محلی** و **خریداران مسن‌تر** (و چند خریدار جوان به‌عنوان کنترل).

## ۱. اهداف تست

| هدف | سؤال کلیدی |
|-----|------------|
| سادگی صفحه اصلی | آیا کاربر در ۳۰ ثانیه می‌فهمد چه کاری باید بکند؟ |
| شهر + اطراف من | آیا انتخاب شهر و «اطراف من» واضح و قابل‌اعتماد است؟ |
| Onboarding فروشنده | آیا فروشنده بدون کمک ویترین + کالا می‌سازد؟ |
| نشان‌های اعتماد | آیا «≈ تقریبی» و تیک آبی درست درک می‌شوند؟ |
| Empty state | وقتی نتیجه‌ای نیست، آیا مسیر بعدی روشن است؟ |

## ۲. شرکت‌کنندگان پیشنهادی

- **۵ فروشنده محلی** (مغازه‌دار، صنف‌های مختلف، سن ۳۵–۶۰)
- **۵ خریدار مسن‌تر** (۴۵–۷۰ سال، کاربر عادی موبایل)
- **۳ خریدار جوان** (۲۰–۳۵) برای مقایسه

زمان هر جلسه: **۲۵–۳۵ دقیقه** (حضوری یا تماس تصویری + اشتراک صفحه).

## ۳. سناریوهای وظایف (Task scenarios)

### خریدار
1. بدون ثبت‌نام، کالای مشخصی (مثلاً «لاستیک») در شهر خودت پیدا کن.
2. شهر را عوض کن و ببین نتایج عوض می‌شود.
3. «کالاهای اطراف من» را بزن (یا اگر اجازه نداد، شهر را دستی انتخاب کن).
4. یک کالا را باز کن؛ بگو قیمت قطعی است یا نه؟
5. وقتی چیزی پیدا نشد، چه می‌کنی؟

### فروشنده
1. وارد شو / ثبت‌نام کن و ویترین بساز (نام، شهر، توضیح).
2. یک کالا با عکس و قیمت اضافه کن؛ پیش‌نمایش زنده را ببین.
3. لینک ویترین را کپی/اشتراک کن.
4. اگر کالایی نداشتی، صفحه خالی چه می‌گوید؟

## ۴. سؤالات بعد از جلسه (۵ دقیقه)

- در یک جمله بگو کی‌داره چیست؟
- چه چیزی گیج‌کننده بود؟
- به یک همکار/دوست پیشنهاد می‌دهی؟ چرا؟
- برای خرید حضوری چقدر اعتماد می‌کنی؟ (۱ تا ۵)

## ۵. معیارهای موفقیت

| معیار | هدف |
|-------|-----|
| تکمیل وظیفه خریدار بدون کمک | ≥ ۸۰٪ |
| درک «قیمت تقریبی» | ≥ ۷۰٪ |
| ساخت ویترین + یک کالا توسط فروشنده | ≥ ۷۰٪ در جلسه اول |
| زمان تا اولین جست‌وجوی معنادار | < ۴۵ ثانیه |
| امتیاز اعتماد (۱–۵) | میانگین ≥ ۳.۵ |

## ۶. نحوه ثبت

برای هر شرکت‌کننده یادداشت کن:

- کجا گیر کرد / چند بار پرسید
- نقل‌قول کوتاه (exact words)
- پیشنهاد خودش برای بهبود

قالب ساده:

```
نام / نقش / سن تقریبی:
وظیفه ۱: موفق / کمک لازم / ناموفق — نکته:
وظیفه ۲: ...
نقل‌قول:
پیشنهاد:
```

## ۷. بعد از تست

1. مشکلات را بر اساس **تعداد تکرار** اولویت‌بندی کن.
2. فقط تغییرات با impact بالا را در اسپرینت بعدی بگذار.
3. این سند را با نتایج واقعی در `docs/UX_TEST_RESULTS.md` تکمیل کن.
