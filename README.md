## 🎯 درباره کی‌داره

**کی‌داره** یک نرم‌افزار پیشرفته برای ساخت و مدیریت **ویترین آنلاین فروشگاه** است؛ طراحی‌شده برای کسب‌وکارهایی که فروش را حضوری انجام می‌دهند اما نمی‌خواهند فقط به عبور عابر پیاده یا شانس تکیه کنند.

با کی‌داره فروشنده در چند دقیقه ویترین خودش را بالا می‌آورد، کالاها را با قیمت و توضیح شفاف می‌چیند، لینک ویترین را در واتساپ و شبکه‌های اجتماعی پخش می‌کند و مشتری را **به سمت فروشگاه** می‌کشاند — نه اینکه منتظر بماند کسی از در وارد شود.

خریدار بدون ساخت حساب می‌تواند جست‌وجو کند، ویترین‌ها را ببیند، کالا را ذخیره کند و برای بازدید حضوری هماهنگ شود. تمرکز روی **کشف کالا + هماهنگی حضوری** است؛ سبد خرید اینترنتی، پرداخت آنلاین سفارش یا ارسال پستی در این نسخه تعریف نشده.

## ⚡ چرا کی‌داره؟

| مشکل رایج فروش حضوری | پاسخ کی‌داره |
| --- | --- |
| ویترین فقط داخل مغازه دیده می‌شود | ویترین آنلاین همیشه در دسترس است |
| مشتری نمی‌داند چه داری | جست‌وجو، دسته‌بندی، شهر و نزدیک‌من |
| باید منتظر بمانی کسی رد شود | لینک ویترین را بفرست؛ مشتری را بکش |
| تماس و هماهنگی پراکنده است | چت داخل برنامه + شماره تماس روی کالا |
| تبلیغ گران و پیچیده است | بسته‌های دیده‌شدن، تگ کالا، تیک آبی |

**شعار عملیاتی:** ویترینت را آنلاین کن. منتظر نمان. مشتری را بیاور.

## 🧭 هدف و شیوه کار

### برای فروشنده — از امروز ویترینت را زنده کن
1. با شماره موبایل ثبت‌نام و تأیید کن.
2. ویترین فروشگاهت را بساز (نام، شهر، آدرس، ساعات، توضیحات).
3. کالاها را با قیمت، توضیح، تصویر و در صورت نیاز مختصات اضافه کن.
4. لینک ویترین و کالا را در واتساپ، استوری و پروفایل کسب‌وکار پخش کن.
5. با چت یا تماس، بازدید حضوری را هماهنگ کن و بفروش.

### برای خریدار — سریع پیدا کن، حضوری هماهنگ کن
1. بدون حساب، کالا و ویترین‌ها را جست‌وجو کن.
2. فیلتر شهر، دسته یا «نزدیک من» را اعمال کن.
3. کالا را ذخیره کن یا فروشگاه را دنبال کن.
4. چت کن یا تماس بگیر و برای خرید حضوری قرار بگذار.

> کی‌داره جایگزین مغازه نیست؛ **موتور جذب مشتری به مغازه** است.

## ⭐ قابلیت‌ها

### 🛍️ برای خریدار
- مشاهده عمومی کالاها و ویترین‌ها بدون نیاز به حساب
- جست‌وجو، فیلتر دسته و شهر، جست‌وجوی نزدیک (مختصات + شعاع)
- صفحه مستقل هر کالا و هر ویترین با قابلیت اشتراک‌گذاری
- ذخیره کالا (مهمان: در مرورگر؛ کاربر واردشده: در سرور)
- دنبال‌کردن ویترین‌ها
- گفت‌وگوی مستقیم با فروشنده از صفحه کالا
- شماره تماس فروشنده روی جزئیات کالا برای هماهنگی سریع حضوری

### 🏪 برای فروشنده
- ساخت ویترین حرفه‌ای در چند دقیقه — بدون منتظر ماندن برای مشتری عبوری
- مدیریت کامل کالا: افزودن، ویرایش، حذف، تصویر JPG/PNG/WebP (حداکثر ۴ مگابایت)
- ویرایش پروفایل ویترین: نام، شهر، دسته، آدرس، ساعات، تماس، توضیح، خرید حضوری
- لینک و متن آماده برای پخش در واتساپ و شبکه‌های اجتماعی
- بسته‌های دیده‌شدن: اولویت جست‌وجو، استوری بازار، بنر محلی، تیک آبی، تگ کالا
- پنل فروشنده برای مدیریت ویترین و تگ‌ها

### 🔐 ورود و حفاظت
- ورود و ثبت‌نام فقط با OTP پیامکی (کاوه‌نگار)
- کپچای محاسباتی و پذیرش قوانین
- CSRF روی عملیات تغییردهنده
- اعتبارسنجی سمت سرور برای داده و تصویر (بر اساس امضای فایل، نه پسوند)
- محدودیت نرخ ارسال OTP (شماره و IP)

### 🧰 عملیات و رشد
- گزارش تخلف کالا/ویترین و صف مدیریت
- تیکت پشتیبانی و داشبورد ادمین
- PWA قابل نصب روی موبایل
- پشتیبان‌گیری و بازیابی SQLite

## 🚀 راه‌اندازی در رایانه شخصی

### پیش‌نیازها
- Python نسخه ۳.۱۰ یا جدیدتر
- pip
- دسترسی به ترمینال یا خط فرمان

### ۱. دریافت پروژه

```bash
git clone https://github.com/Tahmoures54/kidareh-pf.git
cd kidareh-pf
```

### ۲. ساخت محیط مجازی

**ویندوز:**

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

اگر PowerShell اجازه فعال‌سازی نداد:

```bat
.venv\Scripts\activate.bat
```

**لینوکس یا macOS:**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### ۳. نصب وابستگی‌ها

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### ۴. اجرای برنامه

```bash
python main.py
```

سپس در مرورگر:

**http://127.0.0.1:5000**

در اجرای نخست، پایگاه داده SQLite مقداردهی می‌شود. برای توقف: `Ctrl+C`.

## ⚙️ تنظیمات محیطی

| متغیر | کاربرد | مقدار پیش‌فرض |
|---|---|---|
| `SECRET_KEY` | کلید امضای نشست Flask | در production اجباری؛ در توسعه اگر نباشد یک کلید تصادفی موقت ساخته می‌شود (نشست‌ها با ری‌استارت پاک می‌شوند) |
| `DATABASE_PATH` | مسیر فایل SQLite | `instance/kidareh.sqlite3` |
| `PORT` | درگاه وب‌سرور | `5000` |
| `KAVENEGAR_API_KEY` | کلید پیامک کاوه‌نگار | تنظیم‌نشده |
| `KAVENEGAR_VERIFY_TEMPLATE` | الگوی تأیید OTP | `verify` |
| `KAVENEGAR_TEMPLATE` | نام جایگزین الگو | `verify` |
| `KAVENEGAR_TIMEOUT_SECONDS` | مهلت پاسخ پیامک (۲–۲۰) | `10` |
| `UPLOAD_FOLDER` | مسیر تصاویر | `static/uploads` |
| `ZIBAL_MERCHANT` / `ZIBAL_MERCHANT_ID` | درگاه پرداخت زیبال | بدون آن پرداخت غیرفعال |
| `ADMIN_PHONE` | شماره مدیر | تنظیم‌نشده |

نمونه لینوکس/macOS:

```bash
export SECRET_KEY="یک-کلید-تصادفی-طولانی-و-منحصر-به-فرد"
export DATABASE_PATH="/مسیر/پایدار/kidareh.sqlite3"

```

ویندوز PowerShell:

```powershell
$env:SECRET_KEY = "یک-کلید-تصادفی-طولانی-و-منحصر-به-فرد"

```

**امنیت:** کلیدهای واقعی و `SECRET_KEY` را در کد یا مخزن عمومی قرار نده.

## 📲 پیامک و ورود با شماره موبایل

برای فعال‌کردن OTP، در محیط اجرا تنظیم کنید:

- `KAVENEGAR_API_KEY`
- `KAVENEGAR_VERIFY_TEMPLATE` (یا `KAVENEGAR_TEMPLATE`)
- `KAVENEGAR_TIMEOUT_SECONDS` (۲ تا ۲۰ ثانیه)

سرویس از endpoint رسمی `verify/lookup.json` استفاده می‌کند. کد شش‌رقمی پنج دقیقه اعتبار دارد؛ حداکثر پنج تلاش. ارسال مجدد حداقل پس از ۶۰ ثانیه. سقف: ۳ درخواست در ساعت برای هر شماره و ۱۰ برای هر IP.

جریان ثبت‌نام سه مرحله دارد: انتخاب نقش ← تأیید شماره با کد پیامکی ← تکمیل پروفایل. حساب کاربر **فقط بعد از تأیید پیامک و در مرحلهٔ تکمیل پروفایل** ساخته می‌شود؛ یعنی نام و اطلاعات ویترینی که کاربر وارد کرده ذخیره می‌شود و هیچ حسابی با نام پیش‌فرض ساخته نمی‌شود.

ورود با رمز عبور غیرفعال است. بدون کلید معتبر، در production درخواست پیامک fail-closed است.

## 🚢 استقرار و نگهداری

```bash
gunicorn main:app
```

در production:

1. `SECRET_KEY` قوی و اختصاصی تنظیم کن (بدون آن برنامه بالا نمی‌آید).
2. دیسک پایدار برای SQLite و تصاویر (`DATABASE_PATH`، `UPLOAD_FOLDER`).
3. پشتیبان منظم با `scripts/backup_sqlite.py` و آزمایش `scripts/restore_sqlite.py`.
4. کاوه‌نگار، زیبال و `ADMIN_PHONE` را فقط در محیط امن تنظیم کن.
5. ثبت‌نام، ویترین، کالا، ذخیره، follow و پرداخت را بعد از deploy تست کن.

همهٔ workerها هنگام بالا آمدن `initialize_database()` را اجرا می‌کنند؛ این کار با یک قفل SQLite (`kidareh-migrations.lock` کنار فایل دیتابیس) سریال می‌شود تا دو worker همزمان مهاجرت نکنند و روی `schema_migrations` برخورد نکنند. جداول ویژگی‌ها (از جمله `content_reports` و `otp_rate_limits`) هم در همین مرحلهٔ آغازین ساخته می‌شوند، نه هنگام پاسخ به درخواست.

**هشدار:** فایل‌سیستم موقت پلتفرم میزبانی داده را از بین می‌برد. SQLite برای شروع سبک است؛ با رشد ترافیک، PostgreSQL را بررسی کن.

### نگهداری پایگاه داده

```bash
python scripts/maintain_db.py --report    # فقط گزارش حجم و تعداد ردیف‌ها
python scripts/maintain_db.py             # ANALYZE + PRAGMA optimize + checkpoint
python scripts/maintain_db.py --vacuum    # خارج از ساعات شلوغی؛ کل فایل بازنویسی می‌شود
```

`ANALYZE` را هفتگی و بعد از هر درون‌ریزیِ دسته‌ای اجرا کن؛ برنامه‌ریزِ پرس‌وجوی SQLite بر اساس همین آمار تصمیم می‌گیرد.

## 📈 آمادگی برای مقیاس بزرگ

اندازه‌گیری‌شده با **۱,۰۰۰,۰۰۰ کالا و ۱۰۰,۰۰۰ ویترین** روی ماشین ۲ هسته‌ای / ۴ گیگابایت:

| مسیر | میانهٔ زمان پاسخ |
| --- | --- |
| `GET /` | ۲.۵ میلی‌ثانیه |
| `GET /api/listings` (صفحهٔ اول) | ۳.۵ میلی‌ثانیه |
| `GET /api/listings` (صفحهٔ عمیق) | ۲.۸ میلی‌ثانیه |
| `GET /api/listings?q=…` (جست‌وجوی متنی) | ۵.۹ میلی‌ثانیه |
| `GET /api/listings?city=…&category=…` | ۲.۸ میلی‌ثانیه |
| جست‌وجوی نزدیک من | ۲۴.۷ میلی‌ثانیه |
| `GET /api/stores` | ۱.۷ میلی‌ثانیه |
| `GET /sitemap.xml` | ۰.۵ میلی‌ثانیه |

بازتولید اعداد:

```bash
python scripts/scale_profiles.py --listings 1000000 --stores 100000
```

چه چیزی این اعداد را حفظ می‌کند (هنگام تغییر پرس‌وجوها رعایت شود):

- **صفحه‌بندی از نوع keyset است (`before_id`)، نه `OFFSET`.**
- **ایندکس‌های مرور، ستون‌های مرتب‌سازی را هم دارند:** چون مرتب‌سازی `featured DESC, id DESC` است، ایندکس‌ها به شکل `(category|city, featured DESC, id DESC)` هستند. حذف `featured` از ایندکس هزینهٔ یک پرس‌وجو را در این مقیاس به ۲۵۰ میلی‌ثانیه می‌رساند.
- **جست‌وجوی متنی پنجره دارد:** یک واژهٔ پرکاربرد می‌تواند صدها هزار ردیف را匹配 کند؛ فقط ۵,۰۰۰ موردِ جدیدتر به جدول کالاها وصل می‌شوند (`FTS_SEARCH_WINDOW`).
- **شمارنده‌های ویترین با زیرپرس‌وجو محاسبه می‌شوند،** نه `LEFT JOIN` + `GROUP BY`.
- **هر درخواست یک اتصال دیتابیس دارد** که در تمام پرس‌وجوهای همان درخواست reuse می‌شود.

### محدودیت نرخ درخواست‌ها

محدودیت‌ها در یک جدول مشترک دیتابیس (`kidareh/services/rate_limits.py`) نگه داشته می‌شوند، پس همهٔ workerها یک بودجه را اعمال می‌کنند. کلید، شناسهٔ کاربر است (در نبود آن IP) و به‌صورت هش‌شده ذخیره می‌شود.

| عمل | سقف | فاصلهٔ اجباری |

## 💳 درآمدزایی فروشگاه‌ها

فروشندگان می‌توانند بسته‌های زمان‌دار بخرند: اولویت نمایش، استوری بازار، بنر محلی، تیک آبی، تگ حراج/ویژه/تخفیف. درگاه: **زیبال**. بدون `ZIBAL_MERCHANT` پرداخت واقعی فعال نمی‌شود. نتیجه فقط پس از تأیید سرور زیبال اعمال می‌شود.

## 📍 جست‌وجوی نزدیک و PWA

- با اجازه مرورگر، کالاهای دارای مختصات در شعاع قابل تنظیم (پیش‌فرض ۲۵ کیلومتر) پیدا می‌شوند.
- فقط کالاهایی که فروشنده مختصات ثبت کرده در نتایج نزدیک دیده می‌شوند.
- PWA پوسته و فایل‌های ایستا را کش می‌کند؛ برای نصب به HTTPS نیاز است.

## 🧰 گزارش تخلف، گفت‌وگو و پشتیبانی

- `POST /api/reports` برای گزارش کالا یا ویترین
- چت خریدار و فروشنده از جزئیات کالا؛ مسیر `/messages`
- تیکت پشتیبانی در `/support`
- داشبورد ادمین با `ADMIN_PHONE`؛ مسدودسازی کاربر، پاسخ تیکت، مدیریت گزارش

عملیات تغییردهنده به CSRF و احراز هویت نیاز دارند.

---

## 🛡️ امنیت و حریم خصوصی

- CSRF روی درخواست‌های تغییردهنده
- بررسی مالکیت در ویرایش/حذف کالا و ویترین
- کنترل نوع و حجم تصویر؛ حذف فایل از دیسک همراه با حذف آگهی
- محدودیت نرخ OTP و گزارش تخلف
- در production مقدار پیش‌فرض `SECRET_KEY` پذیرفته نمی‌شود و در توسعه هرگز از کلیدِ ثابتِ داخل کد استفاده نمی‌شود
- پاسخ‌ها شامل هدرهای پایهٔ سخت‌سازی (`nosniff`، `Referrer-Policy`، `X-Frame-Options` و در production روی HTTPS مهلت `Strict-Transport-Security`) هستند

پروژه هنوز ممیزی امنیتی مستقل نشده است. پیش از عرضه گسترده، سیاست حریم خصوصی، نظارت محتوا و سخت‌سازی استقرار را تکمیل کن.

## 🚀 نسخهٔ عمومی و PWA (پیش‌نویس v1.0.0)

- **فونت:** Vazirmatn به‌صورت self-hosted در `static/fonts/` (بدون Google Fonts).
- **طراحی:** توکن‌های یکپارچه در `static/css/style.css`، کامپوننت‌ها در `static/css/components.css`، dark mode خودکار.
- **نصب اپ:** بنر نصب سفارشی پس از ۱۵ ثانیه، اسکرول ۵۰٪ یا کلیک روی کالا؛ راهنمای iOS؛ میانبرهای جستجو، ثبت آگهی و پیام‌ها.
- **بروزرسانی:** Service Worker با `CACHE_VERSION` و Toast تأیید بروزرسانی.
- **SEO:** `/sitemap.xml`، `/robots.txt` و JSON-LD برای کالا و ویترین.
- جزئیات انتشار و وضعیت هر مورد: [`docs/RELEASE_CHECKLIST.md`](docs/RELEASE_CHECKLIST.md)
